# 🛠️ راهنمای گسترش دیتابیس

این سند توضیح می‌دهد چطور دیتابیس را با ابزار جدید، متخصص جدید یا بخش جدید گسترش دهید — بدون شکستن چیزهای موجود.

## فلسفه: داده ← اسکریپت ← خروجی

کل ریپو از یک اصل پیروی می‌کند: **خروجی‌ها هرگز دستی ویرایش نمی‌شوند.** همیشه داده را تغییر دهید، سپس اسکریپت را اجرا کنید:

```
data/*.json ──▶ scripts/build_* ──▶ deliverables/*
   ↑ شما اینجا ویرایش می‌کنید      ↑ اینها بازتولید می‌شوند
```

## افزودن یک ابزار جدید

۱. در `scripts/gh_collect.py` دیکشنری `REPOS` را پیدا کنید و ریپو را به زیربخش مربوطه اضافه کنید:

```python
"07-فرانت‌اند": {
    "فریمورک‌ها": [
        ("facebook/react", "محبوب‌ترین کتابخانه UI جهان"),
        ("owner/new-repo", "توضیح کوتاه فارسی"),   # ← سطر جدید
    ],
},
```

۲. ستاره واقعی را واکشی کنید (از ریشه ریپو):

```bash
python3 scripts/gh_collect.py
```

اسکریپت فقط ریپوهای جدید/ناموفق را می‌گیرد و به `data/gh_data.json` اضافه می‌کند. اگر ریپویی 404 بود:
- نام owner/name را در [github.com](https://github.com) چک کنید — احتمالاً rename شده (مثال واقعی: `listmonk-app/listmonk` → `knadh/listmonk`).

۳. خروجی‌ها را بازسازید:

```bash
python3 scripts/build_xlsx.py          # اکسل ۲۲ شیتی
node scripts/build_docx.js             # ورد (npm install docx اگر ندارید)
```

## افزودن یک متخصص جدید (کارت شبیه‌ساز)

فایل `scripts/build_specialists.py` را باز کنید و با تابع کمکی `add()` کارت جدید بسازید:

```python
add(
    "نقش فارسی", "Role English", "مرحله N — نام بخش",
    "مأموریت یک‌خطی",
    ["مهارت ۱", "مهارت ۲", "...۶ مورد"],                       # skills
    [("نام ابزار", "owner/repo")],                              # stack → ستاره خودکار از gh_data.json
    [("پلتفرم", "url", "توضیح تمرین")],                          # practice
    ["گام ۱", "گام ۲", "گام ۳", "گام ۴"],                       # path
    "سوال مصاحبه شبیه‌ساز؟"                                      # interview
)
```

سپس: `python3 scripts/build_specialists.py && node scripts/build_docx.js`

نکته: ریپوهای ستون `stack` باید در `data/gh_data.json` موجود باشند وگرنه به‌جای ستاره «—» می‌گذارد — اول `gh_collect.py` را اجرا کنید.

## افزودن پلتفرم تمرین

`data/practice_data.py` → دیکشنری `PRACTICE` → کلید تخصص (اگر تخصص جدید است، کلید جدید بسازید). این داده در **اکسل** (شیت «شبیه‌ساز و تمرین») استفاده می‌شود؛ برای دیده‌شدن در ورد، فیلد `practice` کارت مربوطه در `build_specialists.py` را هم کامل کنید.

## افزودن یک بخش کاملاً جدید

۱. `scripts/gh_collect.py`: کلید جدید `"20-نام بخش": {...}` اضافه کنید + اجرا.
۲. `scripts/sections_data.json` با اجرای extractor به‌روز می‌شود (بهروزرسانی دستی هم مجاز است — ساختار: `[[بخش, [[زیربخش, [(ریپو, توضیح)...]]...]]...]`).
۳. برای ورد: کارت‌های متخصص آن بخش را در `build_specialists.py` با بخش `"مرحله ۲۰ — نام بخش"` بسازید.
۴. هر دو خروجی را بازسازید.

## به‌روزرسانی ستاره‌های فصلی

```bash
# کل دیتابیس را تازه کنید (غیرمخرب؛ فقط مقادیر موجود را رفرش می‌کند)
rm data/gh_data.json && python3 scripts/gh_collect.py
python3 scripts/build_xlsx.py && node scripts/build_docx.js
git commit -am "refresh stars $(date +%F)"
```

هشدار: حذف `gh_data.json` تاریخچه واکشی را هم پاک می‌کند؛ اگر ریپویی قبلاً rename شده و fallback دستی داشتید، پس از حذف دوباره باید fallback بگذارید.

## خطاهای رایج

| خطا | علت | راه‌حل |
|---|---|---|
| `star pattern not found` | ریپو 404 یا rename | نام صحیح را پیدا و در REPOS اصلاح کنید |
| `short page (0b)` | rate-limit گیت‌هاب | چند دقیقه صبر؛ اسکریپت resume-able است |
| ستون ستاره «—» در ورد | ریپو در gh_data.json نیست | `gh_collect.py` را اجرا کنید |
| `Cannot find module 'docx'` | پکیج نصب نیست | `npm install docx` |

## قراردادها

- نام بخش‌ها: `NN-نام فارسی` (اکسل) و `مرحله N — نام فارسی` (ورد) — هماهنگ بمانند.
- توضیح ابزارها: فارسی روان، حداکثر یک خط.
- کارت متخصص: دقیقاً ۶ مهارت، ۳-۵ ابزار پشته، ۳+ پلتفرم تمرین، ۴ گام مسیر رشد.
